## 官方接口与资料来源

依据本地官方 Android APK 6.10.11，SHA-256：

`02ecd91b74e00df76cfe00eda4c4a9a5bc332231562a171e48d64f45bd418705`

下表表示在官方实现中已找到对应接口，不表示本页面已成功登录或获取资料。

| 阶段 | 官方实现中的接口 | 已确认的作用 |
| --- | --- | --- |
| Passport 短信 | `/v4/code/phone` | 申请手机验证码；登录用途使用 `rawTemplate=login` |
| Passport 验证码登录 | `/v3/user/phoneCodeLogin` 或 `/v6/user/phoneCodeLogin` | 由官方开关选择版本，不能默认两者等价 |
| 业务登录 | `POST user/user/login` | 输入 `uuid`、`token`、`refresh_token`、`region`；不是直接发送手机号的入口 |
| 已授权车辆列表 | `POST vehicle/vehicle/auth-list` | 返回 `List<DeviceBean>`；资料范围由登录账号权限决定 |
| 车辆授权信息 | `POST vehicle/vehicle/auth-info` | 输入 `wnumber`、`vehicle_type`；返回归属等授权信息，不能当作密钥接口 |
| Gen3 资料 | `POST app-api/bluetooth3/auth/v1/session-key/info` | 表单 `sn`、`useCase`；默认 `useCase=1` |

国内旧业务服务的代码默认地址为 `https://api-jhcx-v6-bj.ninebot.com/`，Java2 服务默认地址为 `https://cn-cbu-gateway.ninebot.com/`。官方 `NbHttpHostManager` 可覆盖默认域名；这些地址不是对全部区域、全部版本的固定保证。

### Gen2：`blue_secret` 是 ASCII 内容

`DeviceBean` 已确认映射：

| 服务端字段 | 官方对象属性 | 网页导入时的用途 |
| --- | --- | --- |
| `wnumber` | `wnumber` | 车辆 SN |
| `vehicle_type` | `vehicleType` | 车型信息，仍需核对投屏配置支持范围 |
| `and_mac` | `macAddress` | 蓝牙地址，须校验格式 |
| `ble_name` | `name` | 蓝牙名称 |
| `device_name` | `deviceName` | 车辆名称 |
| `blue_secret` | `blePairPassword` | 已授权账号返回时的蓝牙配对资料 |

官方 `getBlePairPassword()` 将 `blue_secret` 按 `US-ASCII` 转为字节，`getBlePairPasswordHex()` 再将这些字节转成十六进制。因此 **不能看到字符串像十六进制就直接按 hex 解码**。

导入当前 Gen2 测试配置前，须确认资料为 16 个合法 ASCII 字节，再转换成 32 位 `credentials.passwordHex`。缺失、字节数不符、协议不明时应停止导出，不补零、不截断、不由车辆名生成密钥。`blue_secret` 的存在本身不能证明车辆使用 Gen2。

### Gen3：按 SN 请求 `appEnc`

`V3SessionKeyResponse` 包含 `deviceEnc`、`appEnc`、`efTimestamp`、`exTime`、`reTime`、`nonce`、`aad`。官方将 `appEnc` 交给按 SN 保存的 native `session_key_hex`；本项目已分析分支要求 32 位 ASCII hex 表示 16 字节材料。

保留有效期与刷新信息：官方 `exTime`、`reTime` 单位为分钟，不能把一次导出当作永久密钥。完整 Gen3 认证/刷新仍可能需要实时 challenge、response、verify、refresh，不能用这个静态资料接口替代全部认证服务。

SDK 激活 token、账号 token、车辆 `blue_secret`、`appEnc` 是不同材料，不可互换。

## 当前仍需完成的请求链路

1. **Passport 登录签名。** `PassportApiClient.generateHeaders()` 产生 `clientId`、`timestamp`、`sign` 等头；签名计算包含 `clientKey`、URL、请求参数和公共参数。还须核对真实登录所用的区域、版本开关、验证码校验和业务登录响应。
2. **车辆 API 请求加密与响应解密。** `CommonHttpClient` 安装 `BaseParametersInterceptor`，使用 `YiDunSecurityPolicy.encryptor()`。`YiDunRequestEncrypt` 添加 `serviceTime`、`nonce`、`checkcode` 后进入当前策略的加密器。旧策略 `NeteaseDecrypt` 调用 Android `SecruityInfo.encryptStringToServer()` / `decryptStringFromServer()`，新策略走 `YiDunRiskEncrypt`。仅凭接口路径无法据此实现浏览器版本；也没有证据证明服务端接受省略这部分的已登录请求。
3. **账号与车辆资料绑定。** 核对业务 token、公共参数、响应解包及所选 SN；不得把某辆车的资料套到其他车辆。
4. **协议与投屏配置映射。** 5 英寸、半彩屏、7 英寸不能直接决定 `authVersion`、NUS 配置和传输方式，须使用已验证的车辆/仪表配置。

本地 `AuthorizedNinebotProvider` 是 `authorized-ninebot-v1` 用户授权 HTTPS 服务合同，代码已明确它不是官方云 API。不能将上述官方 URL 直接填入它冒充适配完成。

## 与现有 App 的衔接

- Gen2 对应 `authVersion=2` 与 `credentials.passwordHex`。
- Gen3 对应 `authVersion=3` 与 `credentials.v3.sn/appEncHex/metadata` 等已支持字段。
- `profileId`、传输方式和仪表参数须来自已核验配置；云端返回车辆列表不等于本项目支持所有仪表。
- 刷新页面或主动退出时清除内存资料；不把账号 token 放进 URL、浏览器持久存储或诊断日志；复制给 App 的资料不应包含无关账号登录凭据。
- 后续流程仍是 App 完成 BLE 认证和开屏，等待应答后连接 Wi-Fi 并启动媒体，网页负责取得资料。
